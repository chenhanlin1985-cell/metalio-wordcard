# 单词机 SD 诊断工具 1.0.1

适合已经安装“小小单词卡”的无名 S31 前光板，Windows 10/11。**不需要安装 Python，不需要先换诊断固件。** 解压到电脑文件夹后，双击“启动诊断.cmd”。请勿直接在 ZIP 内运行。

1.0.1 修正了真实设备测试中发现的 `chkdsk` 中文日志乱码：按 Windows 系统 OEM 代码页解码其输出，再以 UTF-8 保存报告，不修改系统语言或区域设置。

## 先做设备诊断

1. 让设备开机，以普通学习模式连接 USB，不要进入 U 盘。
2. 如果当前有“无法写入”或“进度问题”，保持在报错页。
3. 双击启动，选 **1**，准备好后回车，采集期间不要点设备。

工具只发送 `web status` 和 `status`，不代答、不导入、不校时、不重启、不刷固件。它会记录当前错误码、SD/RTC 状态，并比较采集前后的完整学习状态指纹。只读状态采集不会主动制造写入失败；没有捕获错误不等于设备永远正常。

多个串口时选择单词机的 COM 口；不要选择别的硬件。若串口被其他烧录/串口软件占用，先关闭占用软件。工具不会通过拉高 DTR/RTS 重置设备。旧版未暴露 errno 时，会如实写“底层错误码不足”，不会猜测坏卡。

## 再做 SD 诊断（能看到 U 盘时）

1. 通过设备正常进入 U 盘模式，或关闭设备后用读卡器连接 SD。
2. 重新双击启动，选 **2**，输入 SD 盘符，例如 `G:`。
3. 等待完成。测试期间不要拷贝文件、拔卡或操作设备。

如果设备因无法保存而拒绝进入 U 盘，**不要强行跳过保护**；先把设备模式的报告发回。有读卡器再进行第二步，没有读卡器也可以先诊断设备错误码。

SD 模式检查空间、文件系统、磁盘只读信息、关键文件的只读属性、目录被同名文件占用、词表路径/大小/UTF-8，以及原生快照和日志的校验和/记录顺序。它不完整重放 FSRS JSON patch，也不重置、截断或修复日志。

随后在已有关键目录内，用随机新建的 8 KiB 临时文件检查创建 → 写入 → 强制落盘 → 追加 → 回读 → 改名 → 删除。只删除本次自己成功创建的随机文件，绝不覆盖已有文件。前后核对已有记录和词表哈希及属性；无法读到的文件标为“未验证”，不冒充通过。

另运行 Windows `chkdsk X:` 的只读检查，不带 `/f /r /x` 或其他修复参数。不需要管理员启动；权限不足会记录为未完成，不自动提权。SD 检查上限90秒，文件系统只读检查上限45秒；超时会停止诊断子进程并标记未完成。只可能遗留 `.__wcdiag_随机编号` 临时文件，不会自动反复重试。Windows若仍显示忙碌，请等可安全弹出后再移除。

## 把报告发回来

完成后自动生成报告 ZIP。双击 **“查看诊断报告.cmd”**，找到最新 ZIP 发回即可。报告默认在 `%LOCALAPPDATA%\WordcardDiagnostics`。

先看 `先看诊断结果.txt`：每条结论分为 `observed`（本次直接观察到）和 `limited`（证据不足或检查未完成）。不要只把末尾的“未改进度”当成“SD 没问题”。

报告包含错误码、文件相对路径/大小/属性/哈希、测试失败阶段和脱敏日志；不会附带词表正文、词义、答案、输入草稿、完整学习记录或照片。已有进度和词表留在卡上。工具不上传数据，需要你手动发回报告。

## 判断边界

- 小文件能写，不代表进度文件没有只读属性，也不代表整张卡无坏块或容量真实。
- 电脑能写，不证明设备端 SDMMC、供电、接触或文件句柄无问题；必须结合设备报告。
- 一个 EACCES/“错误码13”不能直接判坏卡：当前固件的 IDF 会把多种 FAT 拒绝/只读/锁定状态映射成同一个 errno。
- 若确有坏卡或文件系统损坏，下一步先备份，再按证据决定处理。本工具不自动解除只读、格式化或覆盖旧记录。
- 两个模式都没有复现时，结论是“本轮未捕获”，不是“原因已查明”。

高级只读模式：在 PowerShell 运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\diagnose.ps1 -Mode SD -Drive G: -ReadOnly`。这会跳过随机文件写入，只读取元数据、校验记录和文件系统。
